# 设计问答(讨论沉淀)

> 目的:沉淀开发过程中的关键问答,记录决策依据。条目只追加;结论修订时新增条目并标注"取代 N"。
> 状态标签:【已实现 0.0.15.x】/【规划 M11】/【原则】。

---

### 问: 写侧自动摘要何时记录?分几批?
**答**: 三个批次——① 人工摘要(agent 自觉提交);② 重启后首个对账周期一次性补齐陈旧空闲会话;③ 活跃会话转闲后的下一轮。时序由 manifest 标记 + spool 幽灵扫描双重防重。巩固积压用"每日 04:30 对齐 + 启动追赶 90s"兜底,hub 重启不再顺延巩固。【已实现 0.0.15.1】

### 问: agent 是否有效使用了记忆?(自觉率问题)
**答**: 实测某工作区 4 会话 12,436 帧、memory.* 调用为 0——写侧全自动、读侧为零,"只进不出的保险箱"。出路三层:① AGENTS.md 措辞从"应做"改"必须"+用户口令;② 自觉率进 stats 可测量;③ 读侧自动化(见钩子条目)。结论:自觉不可靠,系统必须主动喂。【已实现 0.0.15.2-4】

### 问: harness(DSH/Codex)无法在会话前自动注入,能否劫持用户会话内容加入捞回指令?
**答**: 不需要劫持——DSH 自带官方通道:hooks-claude-code 桥的 SessionStart / UserPromptSubmit 钩子,钩子以 `hookSpecificOutput.additionalContext`(结构化 JSON)输出即可注入下一轮模型请求。用户层补丁挂载($DSH_HOME/cordis.patch.yml),零补丁、双 harness 可用。教训:CC 方言下 plain stdout 只会"rendered as output",必须用结构化 JSON。【已实现 0.0.15.2/0.0.15.3】

### 问: 会话中每次发言,有没有捞回机会?
**答**: 有。UserPromptSubmit 每条消息触发,且以**用户原话当检索词**——比固定查询词精准,会话开头得全景,话题一转捞相关记忆。【已实现 0.0.15.2】

### 问: 每次捞回对上下文窗口影响多大?频率要不要控制?每次都捞合理吗?
**答**: 实测单次 1.5-2k tokens 且**永久留在历史**;最坏推演吃掉 27% 窗口;本会话 6 次注入约 60% 是重复的 L2 块。结论:**检索每次都做(本地毫秒级),注入按条件做**。三道闸:① 内容哈希去重(同内容永不重注);② 内容变化需间隔 ≥10 分钟;③ 琐碎发言(<4 字符)跳过;外加钩子预算 4000→2000。SessionStart 保持全量。【已实现 0.0.15.4】

### 问: 该不该在每次发言里提示 AI 检查是否需要捞回?
**答**: 不加在消息里,加在横幅里(每条消息带提示 = 常驻浪费;横幅在场时提示是废话)。改为**分级注入**:全量横幅(内容变化)/ 领航灯(被跳过但 >30 分钟,~60 字符"库在线 N 条,细节→search")/ 熄灯(琐碎)。危险时刻恰是横幅缺席时,领航灯负责让库的存在始终可见。【规划 0.0.16.0】

### 问: AI 如何判定"记忆丢了"?
**答**: 你无法记得"你不记得的东西",所以不靠自觉,靠两个机制把它变成查目录:
- 机制 A(系统侧,治本):**目录常驻**——记忆库暴露纯标题清单(~200 字符),agent 任何时候可见库里有什么;丢的不是记忆而是"书名可见性",看到目录缺什么一目了然,需要就 memory.search 拉全文。把"猜自己忘了什么"变成"查目录拿全文"。实现:memory.context 加 tocOnly 参数,不加新工具(工具数红线 8 不破)。
- 机制 B(行为侧,治标):AGENTS.md 行为规则,教 agent 三个可疑信号——① 未知指代(用户提"之前/上次/约定"而上下文解析不了→先查再答,禁止编造);② 无出处常量(要引用上下文没有出处的端口/路径/约定→search 优先于猜);③ 新鲜度错位(领航灯显示久未更新而对话推进很多→主动查一次)。【规划 0.0.16.x】

### 问: 记忆的可见性边界?agent 能看别人的记忆吗?
**答**: 不做全局互通。个人记忆经**共识上浮**才公开:agent save(scope=studio)→ needs_review 提案(检索不可见)→ member 裁决 active → 可带冲突候选。开会是达成共识,不是翻阅他人的个人记忆。【已实现 0.0.15.0(M09 Tier-1)】

### 问: 为什么严禁修改 DSH(node_modules)?
**答**: 零补丁原则——改了就无法安全升级,每次 DSH 更新都要重做手术。所有集成走官方表面:插件(cordis patch 行)、钩子(hooks-claude-code 桥)、MCP(hub :45678)。SimpleAIBrain 对 DSH 的全部接触面 = ① 用户层 cordis.patch.yml 一行挂载;② hooks.json + 钩子脚本;③ hub 工具。【原则】

### 问: token 为什么放工具参数(_brainToken)而不是 HTTP Bearer?
**答**: 运维决策:hub MCP 工具的鉴权走参数,避免 token 进 HTTP 头日志/代理日志;脚本读 .brain.json 后即用即弃,永不打印。【原则】
