## 0. 定位

SimpleAIBrain 是 **simpleMCPServer 的进程内插件包**:独立仓库、独立依赖、独立 tsc 构建,由 hub 按配置路径动态加载。职责只有记忆——采集、分层、巩固、检索、注入;不控制外部软件(与 Blender/Unreal 桥分工)。

规模分级:

- 单人/简单项目:仓库根目录的 `session_memory.md`(git 可审计、零设施)足够;
- 跨会话、团队、多 agent:SimpleAIBrain。
- 两者**并存不替代**,衔接靠一次性导入 `memory.import`(v2)。

## 1. 设计原则(系统不变量,任何模块不得违背)

1. **hub 进程独占存储**——所有写物理汇聚同一 Node 进程,"同时只有一个写者"由结构保证,不靠约定。
2. **agent 永不直接触存储**——只经 MCP 工具 / hub 路由。
3. **写入自由(短期),升层受限(长期)**——agent 随意写 L1(会自然衰减);进 L2/L3 必须过证据门槛或人工闸门。
4. **层级是索引,不是坟场**——升层永不删下层;每条 L2/L3 带 `source_ids` 溯源链,可下钻到 L0 原文。
5. **遗忘可逆**——低于存活线 → `archived`(软删除),显式搜索仍可命中。
6. **压缩与存活是两个独立过程**——摘要分层(文本变短)与艾宾浩斯存活评分(条目该不该记)分别实现,防止垃圾被逐层固化。
7. **用户负责,agent 受限**——责任归属靠身份闸门,不靠提示词恳求。
8. **frontmatter 是唯一事实源**——目录只是地址;不信任 mtime。
9. **检索结果是不可信数据**——防记忆投毒:注入上下文的记忆必须可归因(`created_by`);高重要性 L3 的变更必须过人。
10. **允许人工直改大脑,但要留痕**——文件 + git diff 承担审计,不另建 revisions 表。

## 2. 总体架构

```
agents(N) ──MCP──▶ SimpleMcpServer(hub,唯一进程)
                    │
                    ├─ 写入:memory.save / 被动流水 onToolEvent ──▶ L0/L1
                    ├─ 读取:memory.search / memory.context ──▶ 分层加权组装
                    ├─ 巩固:定时任务 ──▶ 摘要/升层/冲突上报/衰减
                    └─ 摄入:hook → /brain/ingest → spool → watcher ──▶ L0
                                 │
                                 └─▶ data/(独立 git 仓库,FileStore)
```

三条泳道之外的一切外来数据(会话摘要、完整 jsonl)都从"摄入"泳道进入。

## 3. 记忆模型概要

| 层 | 内容 | 来源 | 待遇 |
|---|---|---|---|
| L0 | 原始层:被动工具流水(JSONL)+ 提交的完整会话日志 | 摄入/被动记录 | 只给巩固挖,**永不注入上下文** |
| L1 | 会话摘要(每会话一份) | 巩固自 L0 / 提交的摘要 | 自由写入;快速衰减 |
| L2 | 主题/项目级归并 + 抽取事实 | 巩固自 L1 | 需证据门槛 |
| L3 | 原子化单事实(一条一事) | 升层 / 人工写入 / 导入 | 受限写;pin 豁免衰减 |

两个独立过程:**压缩**(L0→L1→L2→L3,有损归纳)与**存活**(逐条打分):

```
R = importance · e^(−Δt / S)        Δt = 距上次访问时长
访问增强:S ← S · (1 + k)            检索命中即复习
R < 地板值 → status = archived       可逆,显式搜索可命中
```

升层由**证据**驱动(跨会话反复命中 / importance / pin),时间只用于衰减方向。

## 5. 路线图

- **v1(MVP)**:M01、M02、M03、M04、M05、M06(先接 Claude+Codex)、M07、M08、M10 的基础项、M11 的强制项(脱敏、投毒标注)。
- **v2**:L3 升层自动化完善、Claude SessionStart 记忆推送、opencode/Cursor 适配、联邦只读 API(registerRoutes)、memory.import。
- **v3**:PgStore、跨工作室发布流、needs_review 完整工作流、向量检索。

切分原则:**v1 结束时,系统对单个 agent 已经"自转"**(被动采集→巩固→检索注入闭环);v2/v3 都是增强,不做也不破坏 v1 数据。

## 6. 工作纪律

- 遵守宿主仓库《Agent工作纪律》:有疑问不脑补先问;删除改移入 .trash;同名不覆盖加版本号;临时文件进 tmp/;版本号 x.y.z.w(z=大功能、w=crud,agent 可操作)。
- 本仓库版本从 `0.0.1.0` 起:文档定稿 = 0.0.1.0;每个模块实现完成 z+1,修复类 w+1。
- 模块实现顺序建议:M02 → M03 → M07 → M08 → M04 → M01(联调)→ M05 → M06 → M10/M11 强制项。存储先行,因为一切都被它约束。
